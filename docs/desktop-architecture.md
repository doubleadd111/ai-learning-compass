# 桌面版架构

## 当前源码：2026.10.14（合并2026.10.13.1—.5）

- schema9增加任务前置关系与提醒稍后/静音，schema10增加task_resources；JSON9包含资料引用且映射新计划/任务ID。迁移、整库恢复、回收站和安排历史采用固定白名单，不把模型连接或Key混入任务快照。旧程序回退须配对升级前数据库。
- workflow提供批量预览/应用、前置DAG与提醒操作，事务校验原指纹并复用预算确认。backup_manager/backup_metadata分开数据库可读性与配套说明可信度，标明自动/手动/保护来源、真实schema和已记录版本。backup_cleanup清理前预览/默认保留手动/保护最新有效点/摘要重检，不把说明损坏当库坏。
- task_detail_ui提供只读四页详情与明确编辑入口；task_resources只保存和验证URL/本地路径，打开外部对象需确认且不直接运行脚本。global_search对一次刷新快照纯查询，feature_search固定白名单只打开界面或提示上下文，关联结果只定位资料页，不扫描文件正文或直接执行功能。
- day_card和today_selected_day仅保存内存中的本周查看日期，实际date.today仍用于逾期。完成/重点/预算按选中日期显示，今天额外包含逾期待办，切换不写状态或日期；小窗口使用纵向滚动而不是压扁卡片。
- month_motion使用同主题QDrag预览图、短时透明度和目标日期动画；生命周期结束统一清理。drop仍由month_view生成提案、明确确认再提交，动画本身没有排期写入权限。维护者已人工验收，自动真实手势工具受限单独保留。
- startup在导入主窗口前给出早期反馈，按ID任务读取和有界解析/备份缓存减少重复工作；真正提交与恢复仍重新校验，不以缓存代替数据新鲜度，不保证所有环境冷启动速度。

## 2026.10.13基线（合并2026.10.12.1—.2）

- schema8新增task_attention、study_events、captures，不更改任务稳定ID或既有学习记录列；schema1—7先备份，再临时副本迁移、完整校验、原子替换。计划JSON7映射事件ID/任务ID，兼容JSON2—6。完整备份包含待安排事项，计划JSON只含该计划已安排任务。
- organizer.py提供展示设置、按日学习证据、收集箱与同ID安排转换；变更与预算检查在同一事务，预览指纹包含新增表。study_events不会随安排历史回放，旧未知日期累计不伪造成按日记录。专注由单调时钟计量、墙上时钟归日，睡眠间隔仍暂停。
- month_view.py的拖放只生成既有统一排期服务的提案；确认时重新校验来源与容量，并复用中文超限确认。captures没有due_date，不参与容量，安排时原子转为手动任务。
- read_scope只覆盖一次同步UI刷新，共享只读SQLite事务及按查询缓存；写入被禁止，退出即清空。运行入口defer_hidden=True，未显示页在导航时刷新，不把数据库内容永久缓存到下一操作。
- capture_hotkey.py仅在用户明确启用时使用RegisterHotKey，不安装键盘钩子；冲突提示、切换失败尝试保留旧键，退出注销。窗口工具沿用ownerless/nonmodal生命周期、既有主题和右端滚轮输入组件。

## 已发布基线与历史设计

版本：2026.10.13 公开试用版。桌面与原有 Streamlit 入口并存，不共享用户数据库。升级说明与累计功能见[发布说明](releases/2026.10.13.md)。

版本制度采用完整年份 `YYYY.M.N` / `YYYY.M.N.T`，由desktop包统一解析、限制构建类型并映射Windows四段资源；指南按“适用版本”标题校验，不能被正文中的测试示例误匹配。主日志按可用版本汇总，旧过程原样归档；见[版本与日志规范](versioning.md)。本次规范调整不重发已发布附件、不修改数据库schema。

本版包含schema7/JSON6、learning_tools.py离线领域服务、learning_ui.py统计/分组步骤/有限周期窗口，以及trash.py事务回收站。保持五页导航，以有上下文的工具窗口进入；上一公开版11使用schema5，回退必须配对旧构建与升级前备份。

- 统计是按任务due_date归属的当前快照；累计专注与人工补记不能反推发生日。逐日双横条使用共享分钟尺度并直接标值，不合并日期；原数保留在明细，离线总结不调用模型。
- tool_windows管理无Qt父窗口/无native owner的非模态工具，强引用、单例key、最小化恢复、finished回调与统一退出；普通窗口无需exec，安全确认仍为短流程。guide只对真正模态来源设置临时owner。action_menu复用PopupSurface统一分类操作。
- task_search为纯展示层查询，组合名称/说明/完成标准/安排日期、多关键词、状态与日期范围，不更改学习状态或容量口径。计划库固定独立任务箱用虚拟来源__standalone__读取plan_id IS NULL，selected_plan_id仍为None并限制计划专属操作；没有新增假计划或迁移独立任务。
- 今日“查看已完成”只纳入due_date=今天的完成任务，默认仍是今天及逾期未完成；因为没有历史完成时间字段，不声称按实际完成时刻检索。完整已完成独立任务从任务箱全日期查询。
- task_details保存阶段名和最多40个一层步骤；步骤打卡不重复计时，不自动完成父任务。阶段和步骤文字纳入安排版本，勾选状态按学习证据保护；预览来源指纹涵盖新增表，计时/步骤/规则变更均使旧预览失效。
- task_series和series_tasks保存有限周期与各次任务/日期关联。最长一年、明确结束、整体预览再事务保存；规则不在启动或打卡时自动补建。停止操作逐项预览后移除今天起无记录且不在专注的实例，外键SET NULL保留删除标记，避免再次生成。周期规则不通过安排回溯重新激活。
- JSON6映射新计划、任务、周期ID并验证全部关联；完整备份包含独立周期/步骤及回收站，schema1–6在临时副本升级到7后校验与原子替换。没有新增外部依赖，也不访问Key。
- trash仅接收用户明确删除的计划和手动任务，固定表/字段白名单保存实体快照；捕获与删除、恢复与移除回收站项均为同一事务。计划包含历史/暂停/周期资料，单次任务只恢复原记录及仍存在的周期关联，不开启已停止规则。没有settings/connections/Key；30天后禁用恢复、主动四字确认才物理清除。恢复先SAVEPOINT只读预览，指纹包含学习记录/历史/回收站及原排期预算；提交重校验，ID冲突不覆盖，新增容量超限沿用回滚后二次确认。
- 恢复提案可携带单项task的target_date，预览/提交共用同一_restore路径，先验证快照再在内存副本更改due_date，原snapshot_json与expires_at不变；计划不接受单日压缩参数。trash.detail为独立只读快照读取，不因期限到期或同ID活跃任务覆盖而改用当前任务；TrashDetailDialog沿用平级ToolWindows，不接TaskDialog保存流程，也不写学习记录。

```text
run_desktop.py → desktop/main.py（单实例、应用生命周期）
                     ↓
             desktop/window.py / dialogs.py（五页界面）
               ├─ guide.py → 同版本Markdown（离线独立使用指南）
               ├─ planning_ui.py → planning.py（草稿状态、有界问答、概略、修改提案）
               ├─ workers.py → gateway.py → 用户选择的模型服务
               │                   └─ Pydantic + 时间约束校验
               ├─ credentials.py → Windows 凭据管理器 / 内存
               ├─ review.py → 延期与难度规则 → 调整预览
               ├─ focus.py → 单调时钟、暂停、幂等累计
               └─ store.py → 本机 SQLite、每日备份、恢复点
```

## 数据边界

- 普通资料存入 `%LOCALAPPDATA%\LearningCompass`。安装目录只包含程序与动态运行库；升级不迁移或清空学习资料。
- 模型连接只保存服务地址、模型和非敏感选项。密钥按连接 ID 保存在 Windows 凭据管理器；不可用时回退到内存。不读取源码目录的 `.env`。
- 每次后台请求持有启动时的配置快照，后续切换不改动进行中的请求。取消后不应用结果；服务端已收到的请求仍可能计费。
- AI 结果只有通过本地结构、周数、学习日和时长校验后才能保存；最多一次修正，SDK 隐式重试关闭。
- 创建流程依次经过资料、最多两轮追问、可展开概略、每日任务预览与保存。各阶段使用结构化返回；只有明确确认才进入下一生成阶段或写入正式计划，未完成内容保存在草稿表。
- 稳定任务 ID 关联进度、提醒与专注记录。局部调整不增删任务，只允许修改白名单范围；已开始、有记录、锁定及已复盘任务受保护。改期与保留任务合并检查每日／每周容量；应用前重新核对计划revision。
- 计划需求与修改意见保存在plan_briefs，完整修改前后快照在plan_versions。近7天（168小时）可预览调整前/后状态并追加回溯事件，只回放安排/设置白名单，保留当前学习记录；事务重检全局指纹，回溯前另建备份。大改创建关联副本，新任务ID与旧进度分离。
- 当前数据库schema5，包含plan_schedules、pause_history及独立手动任务；旧schema1–4及旧备份先复制到临时库迁移，完整校验后原子替换，升级前另建备份。计划JSON5继续接受旧格式，导入创建新ID；整库备份保留独立任务、草稿、预算与完整版本历史。
- scheduling.py提供纯本地排期预览与预算报告，store.write在事务内对比全局日期负荷，新增超载先回滚抛出BudgetExceeded/PlanCapacityExceeded；UI以来源指纹和负荷摘要作单次人工确认重试，其他计划或预算变化后授权失效。AI/自动排期的单计划硬上限不因此放宽。
- 排期元数据区分逻辑学习周数和实际日历结束日。补排仅改变日期，保留任务ID/记录；暂停为起日闭、恢复日开区间，到期恢复持久化一次并跳过暂停期提醒。预览全局指纹包含计划revision、归档、排期和预算，不涉及Key。
- 草稿连接被删除或改址时必须显式重绑定，避免新Key发送到旧地址。Key不进入草稿、需求、版本、日志或备份。

## 可复现检查

安装开发依赖后运行 `python -m pytest -q`。Qt 测试不调用付费服务；网关测试使用本机 HTTP Mock 验证真实 SDK 序列化。

`scripts/build_desktop.py --local-test` 只生成本机目录程序，不生成ZIP或安装包；不带此参数才进行正式打包。构建检查源码摘要未变化。`scripts/verify_desktop.py` 移除外部Python环境并检查冻结启动、重启、单实例、指南生命周期、删除保护及回溯切回。`scripts/verify_desktop_migration.py` 对指定学习库的只读副本迁移并比对原字段摘要，不访问凭据。`scripts/verify_installer.py` 以独立AppId和QA目录检查安装/覆盖升级/卸载，不能操作用户正式安装。

构建采用目录模式，以便替换 Qt 动态库。已有开发环境的 ICU DLL 不应遮盖 Windows 系统 ICU；此冲突已纳入打包过滤。干净 Windows 电脑、真实服务商和操作系统通知的人工验收边界见 [验收记录](desktop-verification.md)。
# 同版本本机补丁：手动任务与明确改期（2026-10-19）

- schema5沿用规范tasks表和其focus_sessions/notifications外键，允许NULL plan_id。manual=1的任务使用week=0、day=NULL，payload保留DailyTask(day=1)，不混入严格生成计划的逻辑学习日。独立任务不是隐藏的伪计划。
- schema1–4先备份，临时副本升级；SQLite tasks重建在暂时禁用外键的独立事务中完成，恢复外键后校验再原子替换。保留ID/记录，对已有专注且未开始任务修正状态，更新所属计划revision阻止旧预览覆盖。
- 手动任务共用任务视图/状态/提醒/专注；加入计划的手动任务参与实际日期容量与全局预算，但不参与AI改写、生成周数/天数校验或逻辑周复盘。JSON5携带manual，旧格式规范化为manual=0。
- 暂停默认只更改可用状态与历史，不重排任务；改期另由exact_date提案驱动，支持明确选择与日期。人工日期变更保护历史完成/复盘及关联计时，保留已有学习记录和AI锁；自动/AI保护独立执行。
- 全局预览指纹包含规范任务状态及内容的哈希，覆盖独立任务的变化，不输出原文。状态提示用轻量圆角专注浮窗，专注提交后原位更新，避免清空表格选中行。
- 人工指定日期与手动任务写入可启用单次PlanCapacityExceeded确认：事务先回滚，来源指纹和负荷签名一致才重试；新导入计划按稳定元数据签名，既有计划按ID。自动排期/AI仍严格校验。未新增持久超限授权或数据库版本。
- 指南打开期间为无父QWidget顶层单例，弹窗来源临时transient owner解决模态遮挡，来源关闭/隐藏后解除；关闭时WA_DeleteOnClose并清空应用/来源别名，仅保留阅读状态，避免隐藏HWND被来源销毁后复用幽灵对象。原生WM_CLOSE、来源DeferredDelete及exec真实按钮链路纳入guide_check冻结自检。专注浮窗不激活、不接收鼠标，退出前移除全应用过滤器。
- confirmations.py提供统一标题/可滚动内容/固定操作区，CapacityConfirmDialog直接读取异常结构化负荷，不依赖QMessageBox详情按钮。localization.py统一Qt标准按钮中文；UI约定见ui-conventions.md，颜色只取主题令牌，不增加依赖或数据库版本。
