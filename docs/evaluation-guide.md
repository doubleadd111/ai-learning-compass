# 计划质量评测说明

当前只有 1 组真实模型冒烟结果。30 组场景的无 API 预检只说明输入合法，**不等于**模型生成质量通过。

## 小样本先行

先运行 `python -m evaluation.run --pilot` 查看 4 组代表性输入；该命令不调用模型。获得 API 预算确认后，才运行 `python -m evaluation.run --live --pilot`。一次小样本最多处理 4 组场景；每组在格式不合规或连接失败时可能重试一次，因此最多发出 8 次请求。报告只代表这 4 组，不能外推到全部 30 组。

| 场景 | 主要限制 |
| --- | --- |
| `short-daily` | 1 周、每天 15 分钟、电脑练习时间有限 |
| `goal2-days3-minutes45` | 4 周、每周 3 天、完成命令行待办工具 |
| `long-weekly` | 8 周、每周只集中学习 1 天 |
| `limited-english` | 4 周、优先中文资料、不预设英文基础 |

## 自动检查与人工抽查

程序自动验证周数、学习日连续编号、任务时长与非空字段；报告还统计重复任务标题和少数模糊产出物。这些规则无法判断任务是否真的好做。

打开生成的 `human-review-*.csv`，至少检查每周第 1 天，并额外检查自动报告标出的重复或模糊任务：

- **可执行性 1–5 分**：1 分是无法照着做；3 分是有动作与产出但验收不清；5 分是零基础学习者能按说明在时限内完成，且产出可检查。
- **先修顺序 是/否**：判断这一任务是否依赖尚未学习的概念或工具。若是，把问题写进备注。
- 留意限制是否得到遵守，例如短时任务是否过满、英语限制是否被忽略。

记录抽查了多少任务、评分分布和具体问题。简历或 README 只能引用实际运行和评分的数据；不能把尚未填写的 CSV 当作人工评测结果。
